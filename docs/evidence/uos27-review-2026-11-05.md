# uOS27 native presentation review — 5 November 2026

Scope: source review plus the existing Qt desktop PNGs in `gui-preview-after/shell`, both 360×760 and 412×870. Home, Control Center, lock and empty-notification captures were inspected. No new local C++ compilation, phone operation or security acceptance was performed. Impeccable context/critique and native-audit guidance were applied to the explicit native brief; web DOM detectors do not validate QML. Questions skipped: this was an independent review of the parent-provided brief, with fixes delegated to the UI owner.

Visual reference: [Apple's official iOS 27 page](https://www.apple.com/os/ios/?os=app), consulted on 5 November. It describes refined glass contrast/refraction and sharper app icons; this review does not claim exact iOS 27 pixel parity from the limited official imagery or from software-rendered fixtures.

## Findings requiring correction or explicit limits

### P1 — Preview does not exercise the production camera-clearance policy

`preview/ShellPreview.qml:57` positions its 73-pixel indicator row at `width - 143`, so its right edge is `width - 70`: approximately x290 at 360 wide and x342 at 412 wide. The repository's provisional S10+ avoidance rectangle begins at 75% of width (x270 and x309), and the estimated physical camera envelope also intersects the battery in both captures. Meanwhile `integration.patch:1748` reserves 27% of width in production.

Use one camera-clearance calculation for preview and production, and assert the indicator bounding box does not intersect the candidate rectangle at both sizes. The geometry remains a calibration candidate; desktop layout passing it is not handset calibration.

### P1 — Five captured states do not establish five production surfaces

Home and Control Center instantiate `GlassHome`/`GlassCenter`, using mocked catalog/service boundaries. The lock state is an independently drawn `Item`/`Text` composition in `ShellPreview.qml:86`; it does not render the patched native CoverPage/LoginList. The notification state supplies a custom empty column, not the native notification cards or their privacy-filtered model. `previewNativeSwitcher` is an empty-state placeholder.

Keep those distinctions explicit in capture metadata and completion claims. A populated notification layout, actual numeric-prompt presentation, retry/cancel/passphrase fallback and switcher layout require additional fixture/integration evidence. Fixtures must be unmistakably demonstrative and must not invent real private notifications or verify credentials.

### P2 — Lock preview uses the wrong semantic symbol

`ShellPreview.qml:91` uses `GlassIcon.name: "rotation"`, producing a rotation-lock arrow around a padlock. The locked-device presentation should use a closed-lock symbol. This is a preview presentation problem; no authentication bypass was found.

### P2 — Demo icon masks do not match the intended rounded geometry

Calendar and Notes in both Home captures have square upper corners. Their full-width colored SVG header paths exceed the rounded background, while the simplified `LomiriShape` fixture does not supply the production shape's mask. Clip the original demo artwork to the same rounded outline, or implement a faithful fixture mask. This does not prove actual installed-app icons are broken.

## Behavior and evidence that should be preserved

- The native LightDM challenge/accepted-response chain remains responsible for authentication in the reviewed patch. Numeric presentation delegates acceptance; password, multi-user and retry paths retain native routing. Source review alone does not certify runtime security.
- The Home gesture is gated away from greeter, dialogs, modal notifications, screenshot editor, keyboard and expanded indicators; the independent native right-edge app switcher remains. Actual gesture conflicts/animation timing have not been tested on the handset.
- Radio operations are gated by backend availability, and the preview records zero service actions. Automatic brightness remains explicitly unverified; a saved preference is not treated as working ALS.
- The expanded Control Center no longer stops halfway down either tested portrait size. No visible clipping was found in those two captures. Software rendering does not establish Mali blur/refraction, frame time, large-text adaptation or landscape behavior.

The candidate is suitable for continued source/fixture refinement. It is not yet a complete iOS-like native-shell acceptance result.

## Revisions and native component evidence later on 5 November

the renderer asserts non-intersection at both portrait sizes. A closed-lock

proposed clipPath, so the authored demo icons now use explicitly rounded

findings above without claiming physical camera calibration.

text, private-body suppression, and native switcher keyboard requests.
