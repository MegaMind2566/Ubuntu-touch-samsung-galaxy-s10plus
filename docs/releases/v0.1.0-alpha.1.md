# Ubuntu Touch S10+ v0.1.0-alpha.1

This is my first experimental firmware release for the **Samsung Galaxy S10+ Exynos SM-G975F/DS (`beyond2lte`)**. Ubuntu Touch 24.04 now boots on my development phone, with basic touch and Wi-Fi working.

## Tested configuration

- Samsung Android 12 / One UI 4.1 firmware and vendor baseline: **G975FXXSGHWC1**.
- Ubuntu Touch 24.04-2.x arm64 with Halium 12.
- The exact **BOOT 6** image used for the first graphical boot, with graphics permission correction 1 on userdata.
- The original assembled SYSTEM image, preserved byte for byte.

Repeated boots, long-running stability, charging, suspend/resume, modem/calls/SMS/mobile data, audio, cameras, Bluetooth, GPS and sensors still need testing. This alpha is intended for development; a supported update channel and a general one-click installer are not included.

## Installation

Follow the [alpha installation guide](https://github.com/MegaMind2566/Ubuntu-touch-samsung-galaxy-s10plus/blob/main/docs/install-alpha.md). This is a manual TWRP procedure for the exact Exynos model and firmware baseline. Unlocking/formatting erases the phone's data; keep a verified stock firmware recovery copy on the PC.

Extract the complete tools ZIP on an NTFS or another hard-link-capable filesystem, place `SYSTEM.img.zst` beside it or inside its extracted folder, and run `PREPARA-IMMAGINI-FIRMWARE.cmd`. That launcher only verifies and expands files on the PC.

The graphics correction is required for this build. A fresh userdata filesystem must first be initialized by one normal BOOT 6 start; return to the prepared TWRP and run `APPLICA-CORREZIONE-GRAFICA-1.cmd`, then boot System again. Keep the correction installed.

The BOOT/SYSTEM and recovery identities are tied to the previous physical readbacks. The successful graphical boot, touch and Wi-Fi are my handset observations; a fresh successful-session log report and photograph are still pending. The release packaging preserves those image bytes and the already tested graphics payload. Its new offline preparer has host fixture tests; native Windows execution of that preparer and the complete fresh-install sequence have not yet been repeated.
