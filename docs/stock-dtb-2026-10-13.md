# HWC1 stock device-tree audit completed

The version-3 Windows extraction supplied the actual `dt.img.lz4` from the
SM-G975F G975FXXSGHWC1 AP package. The audit works on files only. No handset
unlock, reboot, installation or data change was performed.

## Verified input

- Inspection ZIP: 59,251 bytes, SHA-256
  `495947374c9a13e24787e4e0a0e5f2968b3fa7a3864101653efd5db7625e2536`.
- Compressed image: 108,449 bytes, SHA-256
  `f2a8299393a2b4515c5f64962337904429ab048c2190dd43e8fbfcad09129bc7`.
- Decompressed factory image: 8,388,608 bytes, SHA-256
  `3c533aa9c658bd0ba7e3837da3fe8faa3e1e4185272c6052065ce4904801db36`.
- ZIP CRC, collector image SHA-256 and complete LZ4 frame checks pass.
- Target and original stock ZIP hash/size match the previous HWC1 audit.

The original 6 GB firmware archive remains on the user's PC. Its full SHA-256
is collector-reported; only the supplied small audit bundle was independently
hashed here.

## AVB

The image's AVB hash descriptor identifies partition **`dtb`**, confirming that
Samsung's firmware filename `dt.img.lz4` differs from the AVB partition label.
The salted SHA-256 of the 240,528-byte original payload matches its descriptor.
The embedded SHA256_RSA4096 signature verifies, and the public key matches the
previously inspected top-level stock vbmeta's `dtb` chain at rollback location 6.

Stock flags are 0 and the image's rollback index is 0. This audit does not read
the device's rollback counter or bootloader trust store and does not sign the
custom Ubuntu Touch boot image for the stock trust chain.

## Device tree

The DT table uses version 0, 2048-byte pages and one 239,680-byte FDT inside a
239,744-byte table. Its root identifies `samsung,armv8` and
`samsung,exynos9820`, matching the handset assessment and the pinned port's SoC.
The FDT parser checks all 1,117 nodes and 8,367 properties. The base tree's
hardware-revision range is 0 through 255. It contains eight CPU nodes plus the
expected Mali, Exynos UFS, USB/DWC3 and DisplayPort compatible identifiers.

This is a base Exynos tree. Device-specific board configuration also depends
on the stock DTBO overlays audited earlier. SoC agreement does not establish
that every binding works with the custom kernel or that the vendor HALs run.
The physical `dtb` partition size was not part of the earlier handset inventory;
8 MiB is the factory image length, not a new handset size measurement.

## Current result and next prerequisites

The supplied stock boot, recovery, dtbo, vbmeta and dt images have now been
inspected. The candidate retains its earlier build hashes and remains an
experimental, offline image. No kernel/system rebuild is needed for this
inspection-only change.

The next hardware preparation requires backup coverage, current Download-mode
OEM/FRP/KnoxGuard state, a compatible Samsung recovery route and an AVB plan.
No permission to erase or unlock the handset is inferred from providing these
audit files. Vendor runtime and the first Ubuntu Touch boot remain untested.

Full results are in [stock-dtb-report-2026-10-13.json](stock-dtb-report-2026-10-13.json).
Seven new parser tests pass locally, including malformed structure/string
bounds, property overflow, unclosed nodes and invalid tokens. CI runs the
combined Python suite. The actual supplied DTB also passes the offline analyzer.

```bash
python3 scripts/inspect_stock_dtb.py \
  --bundle /path/to/dtb-inspection-inputs.zip \
  --avbtool /path/to/avbtool.py \
  --output /path/to/stock-dtb-report.json
```

The analyzer reuses the avbtool source checksum enforced by the earlier stock
inspector and needs Python lz4. Raw Samsung images are not committed to this
repository.
